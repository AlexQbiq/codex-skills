# Studio Editor Memory

Use this file as the durable starting context for Studio Editor work in this repo.

Treat this note as a codebase-orientation guide first and a historical bug note second.

## Fast Start

- Read `Investigation Workflow`, `Editor Architecture`, and `Symptom -> First Files` before diving into old ticket context.
- Bring a task-specific `Context delta`: design id, before/after snapshots, exact repro steps, expected behavior, scope, and validation target.
- Prefer the smallest safe fix.
- Avoid broad shared-geometry rewrites unless a narrow fix is clearly invalid.

## Investigation Workflow

1. Classify the bug first:
   - mode / selection / click-outside / `Esc`
   - handle / hover / drag-start / pointer lifecycle
   - ghost geometry during drag
   - selected-room or circulation persistence on pointer-up
   - neighbor / door / furniture propagation
   - save / reload / render timing
2. Decide whether the bug is in ephemeral UI state or persistent design state:
   - ephemeral UI state usually lives in the editor/studio store
   - persistent design state usually lives in the design store
3. Compare ghost geometry against final persisted geometry:
   - ghost wrong while dragging -> inspect ghost renderer, stretch tool, behavior, and math helpers
   - ghost right, saved geometry wrong -> inspect pointer-up finalization and room/circulation updater flow
   - geometry right, selection wrong -> inspect selection tools, mouse mode, and shared container listeners
4. Check whether the failure happens before or after neighbor recomputation:
   - selected shape wrong -> behavior and core stretch math
   - neighbors wrong -> updater bridge and neighbor geometry operations
   - doors or furniture wrong -> door/furniture update helpers
5. If the bug changes only after save, reload, or deploy, inspect design state preparation, sync, and server-facing assumptions.

## Editor Architecture

### Runtime Layers

- UI shell and editor page
- Pixi app + viewport + shared containers
- ephemeral editor state store
- persistent design model + sync store
- selection and mouse mode tools
- room and circulation ghost renderers
- stretch runtime and behavior strategies
- neighbor/update bridge
- lookup/snap caches
- geometry engine
- geometry helper and topology library boundary
- durable design mutations

### State Ownership

- The editor store owns ephemeral UI state:
  - current mouse mode
  - selected room / circulation / furniture / door
  - viewport and app refs
  - snap toggles
  - drag / stretch flags
- The design store owns persistent design state:
  - rooms
  - circulation
  - program rows / furniture DB / customization / NFP / flood / columns
  - debounced sync + deploy + history
- Editing bugs often live at the boundary between these two stores, not in one store alone.

### Container Model

- The renderer creates one Pixi app and one viewport.
- It mounts background, working, and foreground containers under a shared main container.
- Studio geometry may live in an inverted Y-axis design coordinate system.
- Room graphics and circulation graphics can render in different containers.
- Ghost handles and stretch interaction often use a shared container, not a room-only container.

### Selection Model

- Room selection, circulation selection, and mouse mode can be stored separately.
- A bug can therefore come from:
  - wrong mode
  - correct mode but wrong selected entity
  - correct selection but stale container interactivity

## Stretch Data Flow

1. Toolbar or click selection sets mouse mode and selection flags.
2. Selected geometry mounts a ghost renderer.
3. Ghost renderer computes a base polygon and owns local pending updates.
4. The stretch tool attaches pointer listeners to the shared container, tracks near edge, movement, moved segment, and ghost geometry.
5. The stretch tool chooses a room or circulation behavior.
6. Behavior delegates movement math to stretch core, chain movement, snapping, rounding, and support-edge helpers.
7. On pointer-up, the stretch tool finalizes geometry and writes a selected-geometry update.
8. The updater watches pending updates, mutates selected room or circulation, recomputes neighbors, updates doors/furniture, and creates/deletes empty rooms if needed.
9. The design store mutates persistent state and triggers sync/history behavior.

## Symptom -> First Files

| Symptom | Start Here | Then Check |
| --- | --- | --- |
| Cannot select, clear, or exit mode | toolbar, mouse mode controller, base select tool | room/circulation select tools, editor store |
| Handles visible but not draggable | stretch tool, handles renderer | ghost renderer mount/unmount, shared container lifecycle |
| Ghost shape wrong while dragging | stretch tool, relevant behavior | stretch core, chain movement, circulation rounding, neighbor search |
| Ghost shape right but saved geometry wrong | pointer-up finalization | updater bridge, design store, design mutations |
| Selected room updates but neighbors do not | updater bridge | neighbor geometry ops, edge support, neighbor search, room search |
| Geometry right but doors or furniture wrong | door/furniture update helpers | move-door helpers, furniture helpers, design mutations |
| Bug only happens for circulation | circulation stretch behavior, circulation ghost renderer | circulation stretch core, rounding helpers, updater utils |
| Bug only happens after save or reload | design store | design helpers, sync flow, server-facing state assumptions |
| Bug depends on zoom or hit testing | stretch tool, handles renderer, viewport controller | current scale, Pixi container hierarchy |
| Black flash, reveal timing, or locked preview | renderer bootstrap, editor shell | lock/reveal timing |

## Fragile Patterns

- Shared pointer-container lifecycle:
  - room and circulation ghost renderers may share the same container for handles and stretch interaction
  - listener teardown in one path can break the other if interactivity is reset too aggressively
- Selection tool listener reset:
  - broad container listener resets can cause mode-switch bugs
- Separate selection sources:
  - room selection, circulation selection, and mouse mode can drift
- Sentinel identifiers:
  - circulation may reuse room update machinery through a sentinel id, so branch conditions matter
- Hidden modifier paths:
  - `Space` can pan the viewport
  - `Alt` can change pointer-up split / empty-space behavior
  - `Tab` can toggle split-edge behavior
  - `Escape` is often centralized in the base selection tool
- Scale-dependent behavior:
  - hit-test thresholds and handle sizes often depend on current scale
  - zoom-dependent bugs are often hit-testing issues, not topology issues
- Bounding-box search:
  - fast room search usually returns broad candidates
  - exact neighbor relevance must be enforced later
- Heavy topology conversions:
  - cleanup tolerances can change topology, not just prettify geometry
- Topology library failure masking:
  - visible failure may be downstream, while the real cause is earlier invalid geometry generation
- Sync and lock side effects:
  - deep design-state watchers can hide whether a bug is UI-only or truly persisted

## Known Root Causes

Use this section for confirmed root causes only.

- Shared stretch-container teardown can disable active handles if another stretch instance still depends on the same container.
- Broad neighbor candidate search must be followed by a second-stage edge/geometry filter; weakening that filter can over-update unrelated rooms.
- Inner circulation movement and room inner movement may require different empty-space decisions.
- Search/cache invalidation matters when lookup-driven flows depend on fresh geometry and counters.
- Cleanup tolerance can either collapse valid boundaries or preserve broken tiny steps.
- Drag-time ghost geometry should avoid finalization cleanup when cleanup can auto-straighten edges or merge adjacent boundaries.
- Circulation stretch can create multiple real islands when a moved edge crosses a rest edge; whole-polygon validity checks can reject meaningful split faces.
- Mode-exit bugs are often centralized in the base selection tool rather than room-specific or circulation-specific tools.
- Canvas reveal timing belongs on a real render-ready signal, not a generic timeout.

## Known Suspects / Architectural Constraints

- Chain or newly exposed neighbors may be lost when the first deletion changes adjacency.
- Sharp circulation ghost angles often appear before final cleanup, usually in stretch math or face reconstruction rather than rendering.
- Edge-centric room stretching does not automatically imply vertex drag support.
- Shared room/circulation stretch state may have room-specific names even when used by both flows.
- Topology errors that mention too few polygon edges usually indicate upstream invalid geometry.

Include these in a fresh thread whenever possible:

- before / after snapshot ids
- affected room counter or circulation
- exact drag direction
- whether `Alt`, `Tab`, `Space`, or `Esc` matter
- whether the bug appears:
  - during ghost drag
  - only on pointer-up
  - only after reload or deploy
- expected invariant:
  - which room should move
  - which neighbors must remain unchanged
  - whether doors, furniture, or empty space should be preserved

## Maintenance Rules

- Prefer codebase lessons over ticket diaries.
- Add historical ticket details only when they reinforce a reusable code lesson.
- Promote a finding to `Known Root Causes` only after code-level validation or a stable repro-backed test.
- Put speculative but reusable insights under `Known Suspects / Architectural Constraints`.
- Add full repro assets only when they materially shorten future debugging.
