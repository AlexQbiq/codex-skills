# Collaboration Suggestions

These are concrete habits that make our work together faster and safer.

## What Already Works Well

- You usually provide a strong repro package: ticket, design id, snapshot ids, and a concrete symptom.
- You challenge broad fixes when the bug looks local.
- You are explicit about branch hygiene and what should or should not be included.

## Suggestions

### 1. State the fix boundary early

If you already know the acceptable scope, say it up front.

Examples:

- `minimal local fix only`
- `okay to refactor helper`
- `dependency upgrade is acceptable`
- `do not add new boolean ops / buffers`

### 2. Define "done" explicitly

For each task, say which finish line matters.

Examples:

- `unit test is enough`
- `must verify live in the design`
- `prepare PR but do not wait for review`
- `full studio test suite required`

### 3. Mark intentional branch dirt clearly

When the branch is dirty on purpose, say what belongs to the branch.

Examples:

- `this branch intentionally contains the previous geometry fix too`
- `ignore everything except useStretchTool`

### 4. Describe the expected geometry outcome in room language

Repro data is excellent, but expected behavior makes solution quality easier to judge.

Examples:

- `room 92 should grow upward like 64 and 90`
- `room 340 should shrink, not disappear`
- `room 294 should remain a single polygon`

### 5. Turn preferences into constraints when needed

If a certain class of fix is risky, say it as a hard boundary.

Examples:

- `do not broaden behavior outside this path`
- `investigate root cause before proposing a workaround`
- `if tooling access blocks you, stop and ask me`

### 6. Use compact workflow instructions for PR tasks

This removes ambiguity and saves a round trip.

Examples:

- `use PR workflow, target staging, do not wait for Copilot`
- `prepare PR, include only files already staged`
- `commit and push, no PR yet`

## What Codex Should Do Better

- Separate `root cause` from `workaround` more clearly.
- Avoid broad fixes when a local fix is still plausible.
- Stop earlier when exact verification is blocked and ask for help.
- State clearly when a fix changes shared behavior versus a narrow path.
