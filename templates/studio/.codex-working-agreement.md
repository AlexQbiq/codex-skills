# Codex Working Agreement

Use this agreement when opening a new bug or implementation task.

## Default Expectations

- Prefer the smallest safe fix.
- Do not include unrelated branch changes in commits or PRs.
- Validate the touched area before pushing.
- If an external dependency or broad refactor looks necessary, pause and say so clearly before committing to it.
- If SSO, browser automation, Mongo, or permissions block exact verification, stop and ask for help instead of guessing.
- For Studio Editor work, load the shared memory note first: `.codex-studio-editor-memory.md`.

## Recommended Task Template

Use this short structure:

```md
Task: <ticket or goal>
Context: <design id / snapshot ids / repro path>
Expected result: <what should change>
Scope: <local fix only / helper refactor allowed / dependency upgrade allowed>
Validation: <unit only / studio suite / live verification / prepare PR>
Branch notes: <optional, if branch is intentionally dirty>
```

For Studio Editor threads, the shortest opener is:

```md
Use $studio-editor-memory-workflow for this Studio Editor task.

Task: <ticket or goal>
Context delta: <design id / snapshot ids / repro path>
Expected result: <what should change>
Scope: <local fix only / helper refactor allowed / dependency upgrade allowed>
Validation: <unit only / studio suite / live verification / prepare PR>
Branch notes: <optional, if branch is intentionally dirty>
```

## Good Example

```md
Task: QBIQ-10036
Context: design_result_id 911286, before 69d36c07b9dbddc2b670fc1d, after 69d36d357bfd1573c47c2430
Expected result: room 92 should update upward like rooms 64 and 90 after inner circulation stretch
Scope: minimal local fix only, avoid broad geometry changes unless proven necessary
Validation: relevant studio tests, then prepare PR
Branch notes: current branch may already contain intended geometry work
```

## PR Workflow Shortcuts

Examples:

- `Use the PR workflow on this branch`
- `Use the PR workflow targeting main`
- `Prepare PR only, do not wait for Copilot`
- `Commit only the staged files and open PR against staging`

## Escalation Rules

Codex should pause and realign when:

- the clean local fix seems invalid
- the proposed fix broadens shared geometry behavior
- the branch contains conflicting unrelated edits
- verification is blocked by access or environment problems

## Review Standard

- Prefer root-cause fixes over broad workarounds.
- Keep fixes narrow unless broader behavior is intentionally being corrected.
- Add regression coverage when the bug can be expressed in a stable test.
- Say explicitly what was verified and what was not.

## How To Use This File

- For a new task, paste the task template and fill only the lines that matter.
- If you are in a hurry, reference this file and give only the task-specific values.
- If a task should break the defaults, say which line is overridden.
- After a solved Studio Editor issue, update `.codex-studio-editor-memory.md` with any reusable root cause, repro asset, or resolved issue note.
